# دليل إدارة حسابات طلاب CTI في Active Directory

**الإصدار:** 1.0  
**تاريخ الدليل:** 17 سبتمبر 2026  
**النطاق:** حسابات الطلاب داخل Active Directory فقط  

> هذا الدليل مخصص للموظفين المسؤولين عن تحديث حسابات الطلاب في Active Directory. الحزمة مصممة لتعمل بدون تعديل الكود: جهّز `users.xlsx` بالشكل الصحيح، ثم شغّل السكربت الرئيسي.

---

## 1. ما الذي تفعله الحزمة؟

الحزمة تنفذ استبدالاً كاملاً لحسابات الطلاب الموجودة داخل المسار التالي:

```text
cti.org
└── CTI
    └── Saudis
        └── Users
            └── students
```

والمسار التقني (Distinguished Name) هو:

```text
OU=students,OU=Users,OU=Saudis,OU=CTI,DC=cti,DC=org
```

عند تشغيل السكربت الرئيسي، ينفذ بالترتيب:

1. **التحقق فقط** من ملف Excel ومن بيئة Active Directory، بدون إنشاء أو حذف أو تعديل أي حساب.
2. **حذف جميع كائنات User** الموجودة داخل `students` وأي Child OU تحتها.
3. **إعادة إنشاء حسابات الطلاب** من ملف `users.xlsx`.

إذا فشل التحقق، **لا يحدث حذف**.  
إذا فشل الحذف، **لا يبدأ الرفع**.

---

## 2. ملفات الحزمة

ضع جميع الملفات التالية في مجلد واحد:

```text
C:\ADImport\
├── users.xlsx
├── 0-Run-All-CTI-Student-Replacement.ps1
├── 1-Verify-CTI-Users.ps1
├── 2-Delete-CTI-Students.ps1
├── 3-Import-CTI-Users.ps1
├── README.md
└── CTI-AD-Student-Management-Guide.pdf
```

### وظيفة كل ملف

| الملف | الوظيفة |
|---|---|
| `0-Run-All-CTI-Student-Replacement.ps1` | السكربت الرئيسي. يشغّل التحقق ثم الحذف ثم الرفع تلقائياً. |
| `1-Verify-CTI-Users.ps1` | تحقق فقط، بدون أي تعديل على AD. |
| `2-Delete-CTI-Students.ps1` | يحذف جميع User Objects داخل OU الطلاب فقط. |
| `3-Import-CTI-Users.ps1` | ينشئ الحسابات من `users.xlsx`. |
| `users.xlsx` | مصدر بيانات الطلاب. يجب أن يكون بنفس الاسم وفي نفس المجلد. |

**للاستخدام المعتاد شغّل الملف رقم 0 فقط.** الملفات 1 و2 و3 موجودة أيضاً للتشغيل المنفصل عند الحاجة الفنية.

## 3. الصلاحيات والمتطلبات

يجب تنفيذ العملية من Windows Server أو جهاز إدارة يستطيع الوصول إلى Domain `cti.org` ويحتوي على PowerShell Active Directory Module.

المطلوب:

- حساب لديه صلاحية قراءة وإنشاء وحذف وتعديل User Objects داخل OU الطلاب.
- تشغيل PowerShell بصلاحية **Run as administrator**.
- توفر وحدة PowerShell التالية:

```powershell
Import-Module ActiveDirectory
```

إذا لم تكن الوحدة موجودة على Windows Server، يمكن تثبيت أدوات AD الإدارية حسب إصدار Windows Server/RSAT قبل استخدام الحزمة.

> لا تستخدم حساباً محدود الصلاحية وتفترض أن العملية نجحت. السكربت سيوقف نفسه عند فشل الوصول أو الصلاحيات، لكن يجب مراجعة النتيجة النهائية والتقارير.

## 4. تجهيز users.xlsx

يجب أن يكون اسم الملف بالضبط:

```text
users.xlsx
```

ويجب أن يكون في **نفس مجلد السكربتات**.

تتم قراءة **أول Worksheet** في الملف، ويجب وضع البيانات في الأعمدة A إلى E بهذا الترتيب:

| العمود | البيانات | الحقل في Active Directory |
|---|---|---|
| A | البريد الإلكتروني | `mail` |
| B | الاسم بالإنجليزي | `Name / CN` |
| C | الاسم بالعربي | `displayName` |
| D | كلمة المرور | كلمة مرور الحساب |
| E | الرقم التدريبي / اسم المستخدم | `sAMAccountName` و `userPrincipalName` |

### مثال

| A | B | C | D | E |
|---|---|---|---|---|
| `441234567@tvtc.edu.sa` | `Ahmed Mohammed Ali` | `أحمد محمد علي` | `Example@1234` | `441234567` |

سينتج عنه تقريباً:

```text
Name              = Ahmed Mohammed Ali
Display Name      = أحمد محمد علي
Email             = 441234567@tvtc.edu.sa
sAMAccountName    = 441234567
UserPrincipalName = 441234567@cti.org
```

### رأس الأعمدة Header

يمكن أن يحتوي الصف الأول على عناوين مثل:

```text
Email | English Name | Arabic Name | Password | Username
```

والسكربت يحاول اكتشاف صف العناوين وتجاهله تلقائياً.

### مهم جداً: تنسيق الأعمدة

اجعل العمودين **D و E بصيغة Text داخل Excel قبل إدخال البيانات**.

السبب:

- كلمة المرور قد تبدأ بصفر أو تحتوي قيمة يعيد Excel تفسيرها.
- الرقم التدريبي قد يبدأ بصفر، وإذا تم تخزينه كرقم فقد يحذف Excel الصفر من البداية.

يفضل أيضاً جعل البريد الإلكتروني نصاً.

### الحقول المطلوبة

الحقول التالية مطلوبة لكل طالب:

- B: الاسم الإنجليزي.
- C: الاسم العربي / Display Name.
- D: كلمة المرور.
- E: الرقم التدريبي / Username.

البريد في A مسموح أن يكون فارغاً، لكن إذا وُضع يجب أن تكون صيغته صحيحة.

## 6. ماذا يحدث أثناء التشغيل؟

### المرحلة 1: VERIFY

السكربت `1-Verify-CTI-Users.ps1` يقوم بالتحقق من:

- وجود `users.xlsx`.
- إمكانية الاتصال بـ `cti.org`.
- وجود OU الطلاب الصحيح.
- وجود بيانات فعلية في Excel.
- الأعمدة والحقول المطلوبة.
- صحة صيغة البريد إذا كان موجوداً.
- طول وصيغة `sAMAccountName`.
- عدم تكرار Username داخل Excel.
- عدم تكرار Name/CN داخل Excel.
- عدم وجود نفس Username أو UPN **خارج OU الطلاب**.
- فحص مبدئي لكلمة المرور مقارنة بسياسة كلمات المرور الافتراضية للدومين.

وجود الحسابات القديمة نفسها **داخل OU الطلاب لا يعتبر فشلاً**، لأن المرحلة التالية مخصصة لحذفها.

إذا نجحت المرحلة تظهر:

```text
RESULT: PASS - safe to continue to deletion.
```

إذا فشلت:

```text
RESULT: FAIL
```

ويتوقف السكربت الرئيسي بدون حذف أي حساب.

## 7. مرحلة الحذف

بعد نجاح التحقق يعطي السكربت الرئيسي تحذيراً ومهلة 5 ثوانٍ. يمكن إلغاء العملية خلال المهلة باستخدام:

```text
Ctrl + C
```

بعدها يبدأ `2-Delete-CTI-Students.ps1`.

### ما الذي يُحذف؟

يحذف:

- **User Objects فقط**.
- الموجودة داخل:

```text
OU=students,OU=Users,OU=Saudis,OU=CTI,DC=cti,DC=org
```

- ويشمل المستخدمين داخل Child OUs التابعة لها إن وجدت.

### ما الذي لا يُحذف؟

السكربت لا يحذف:

- OU `students` نفسها.
- Groups.
- Computers.
- Contacts.
- أي User خارج OU الطلاب المحددة.

قبل الحذف ينشئ ملف CSV يحتوي بيانات وصفية عن الحسابات التي سيتم حذفها، مثل:

```text
DELETED-STUDENTS-BACKUP-20260917-150000.csv
```

ويتضمن مثلاً:

- Name
- DisplayName
- SamAccountName
- UserPrincipalName
- mail
- Enabled
- DistinguishedName
- ObjectGUID
- SID

### تنبيه مهم عن النسخة الاحتياطية

CSV **ليس نسخة احتياطية كاملة من Active Directory**، ولا يحتوي كلمات المرور، ولا يمكن استخراج كلمات مرور المستخدمين الحالية من AD بواسطة هذه الحزمة.

إذا كانت سياسة المؤسسة تتطلب إمكانية استرجاع الحسابات المحذوفة بكامل خصائصها، فيجب التأكد مسبقاً من وجود آلية نسخ احتياطي/استرجاع معتمدة مثل Active Directory Recycle Bin أو System State Backup وفق سياسة المؤسسة.

---

## 8. مرحلة الرفع

إذا اكتمل الحذف بدون أخطاء يبدأ تلقائياً:

```text
3-Import-CTI-Users.ps1
```

قبل إنشاء أي حساب يعيد فحص البيانات مرة أخرى.

كل حساب يتم إنشاؤه أولاً بحالة Disabled، ثم:

1. ضبط كلمة المرور.
2. تفعيل الحساب بعد نجاح ضبط كلمة المرور.

هذا يمنع بقاء حساب Enabled إذا رفض Active Directory كلمة المرور.

إذا تم إنشاء كائن الحساب ثم فشل ضبط كلمة المرور، يبقي السكربت الحساب **Disabled** ويسجل الخطأ في التقرير.

---

## 9. علاقة Username بالأنظمة المرتبطة

القيمة في العمود E هي الرقم التدريبي / Username.

يتم تعيينها إلى:

```text
sAMAccountName = E
```

وإلى:

```text
userPrincipalName = E@cti.org
```

مثال:

```text
E = 441234567
```

ينتج:

```text
sAMAccountName    = 441234567
UserPrincipalName = 441234567@cti.org
```

هذا يحافظ على توافق حساب الطالب مع الأنظمة التي تعتمد على الرقم التدريبي كاسم مستخدم، ومنها ربط LDAP مثل منصة نواة/Forgejo، وفي الوقت نفسه يبقي UPN قياسياً داخل Active Directory.

نظام سم لا يحتاج من هذه الحزمة إلى إعداد مستقل باسم `UsernameAttribute`؛ الحزمة مسؤولة فقط عن إنشاء خصائص AD بصورة صحيحة.

## 10. التقارير التي ينشئها النظام

كل تشغيل ينشئ ملفات CSV مؤرخة في نفس المجلد.

### تقرير التحقق

```text
VERIFY-AD-Users-YYYYMMDD-HHMMSS.csv
```

الحالات الرئيسية:

- `READY`: الصف صالح للمعالجة.
- `FAILED`: توجد مشكلة يجب إصلاحها.

### نسخة بيانات ما قبل الحذف

```text
DELETED-STUDENTS-BACKUP-YYYYMMDD-HHMMSS.csv
```

هذه مرجعية للحسابات القديمة قبل الحذف.

### تقرير الحذف

```text
DELETE-STUDENTS-YYYYMMDD-HHMMSS.csv
```

الحالات:

- `DELETED`
- `FAILED`

### تقرير الرفع

```text
IMPORT-AD-Users-YYYYMMDD-HHMMSS.csv
```

الحالات:

- `CREATED`
- `FAILED`

احتفظ بالتقارير حسب سياسة القسم، خصوصاً تقرير الحذف والرفع الخاص بكل دفعة.

## 11. رسائل النجاح المتوقعة

عند نجاح العملية كاملة تظهر في النهاية:

```text
SUCCESS: VERIFY -> DELETE -> IMPORT completed successfully.
```

وتأكد من أن تقرير الرفع يحتوي على:

```text
Created : <عدد الطلاب>
Failed  : 0
```

بعدها يفضل فتح Active Directory Users and Computers والتحقق عشوائياً من عدة حسابات داخل OU الطلاب.

## 12. ماذا أفعل إذا فشل VERIFY؟

لا تشغّل سكربت الحذف يدوياً لتجاوز التحقق.

افتح أحدث ملف:

```text
VERIFY-AD-Users-*.csv
```

وابحث عن الصفوف ذات الحالة:

```text
FAILED
```

ثم اقرأ عمود `Message`.

أمثلة شائعة:

### Username مكرر داخل Excel

```text
Duplicate username inside users.xlsx
```

الحل: يوجد رقمان تدريبيان مكرران في E. صحح الملف ثم أعد التشغيل.

### Username موجود خارج OU الطلاب

```text
Username already exists OUTSIDE the students OU
```

الحل: لا تحذف الحساب الآخر تلقائياً. تحقق من سبب وجوده ومكانه قبل المتابعة.

### UPN موجود خارج OU الطلاب

```text
UPN already exists OUTSIDE the students OU
```

الحل: راجع الحساب المشار إليه في الرسالة داخل AD.

### الاسم الإنجليزي مكرر

```text
Duplicate English Name/CN inside users.xlsx
```

الحل: لا يمكن إنشاء كائنين بنفس CN داخل نفس OU. عدّل الاسم الإنجليزي بحيث يكون فريداً.

### Password ضعيفة

قد تظهر رسالة عن الحد الأدنى للطول أو Complexity.

الحل: صحح كلمة المرور في D ثم أعد التحقق.

> فحص كلمة المرور في مرحلة VERIFY فحص استباقي. القرار النهائي لقبول كلمة المرور دائماً يعود إلى Active Directory عند تنفيذ Set-ADAccountPassword، وقد توجد سياسات إضافية في البيئة.

---

## 13. ماذا أفعل إذا فشل DELETE؟

السكربت الرئيسي يتوقف تلقائياً ولا يبدأ الرفع.

راجع:

```text
DELETE-STUDENTS-*.csv
```

وابحث عن `FAILED`.

الأسباب المحتملة:

- صلاحيات غير كافية.
- حماية/سياسة على كائن معين.
- مشكلة اتصال مع Domain Controller.
- تغيير في بنية OU أثناء التنفيذ.

بعد معالجة السبب، لا تفترض حالة البيئة. افحص OU الطلاب في ADUC، ثم أعد تشغيل العملية كاملة من البداية إذا كان ذلك مناسباً.

---

## 14. ماذا أفعل إذا فشل IMPORT بعد نجاح الحذف؟

راجع أحدث:

```text
IMPORT-AD-Users-*.csv
```

إذا كان حساب ما قد تم إنشاؤه ولكن فشل إعداد كلمة مروره، سيبقى Disabled.

الأسباب الشائعة:

- Password Policy رفضت كلمة المرور.
- تعارض غير متوقع في خاصية AD.
- انقطاع اتصال بالدومين أثناء التنفيذ.
- صلاحيات إنشاء/تعديل غير مكتملة.

لا تعاود تشغيل سكربت Import عشوائياً على بيئة نصف مكتملة بدون مراجعة التقرير والحسابات الموجودة أولاً، لأن الحسابات التي تم إنشاؤها بنجاح ستصبح تعارضاً في المحاولة التالية.

في هذه الحالة، الطريقة النظيفة غالباً هي معالجة سبب الخطأ ثم إعادة تشغيل **العملية الكاملة** التي تبدأ بالتحقق ثم تنظيف OU وإعادة الاستيراد، بشرط أن تكون بيانات `users.xlsx` صحيحة.

## 15. تشغيل السكربتات بشكل منفصل

### تحقق فقط

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\1-Verify-CTI-Users.ps1
```

هذا آمن من ناحية التغييرات: لا ينشئ ولا يحذف حسابات.

### حذف فقط

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\2-Delete-CTI-Students.ps1
```

**تحذير:** هذا حذف فعلي لكل User داخل OU الطلاب، ولا يقوم بعده تلقائياً بالرفع إذا شُغّل منفرداً.

### رفع فقط

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\3-Import-CTI-Users.ps1
```

لا تستخدمه كبديل عن العملية الكاملة إلا إذا كنت تعرف الحالة الحالية للـAD، لأن وجود حسابات سابقة قد يسبب تعارضات.

## 16. فحص يدوي بعد نجاح العملية

بعد ظهور نجاح كامل، نفذ فحصاً سريعاً:

1. افتح **Active Directory Users and Computers**.
2. انتقل إلى:

```text
cti.org\CTI\Saudis\Users\students
```

3. اختر عدة طلاب عشوائياً.
4. تحقق من:
   - الاسم الإنجليزي في Name/CN.
   - الاسم العربي في Display Name.
   - البريد.
   - الرقم التدريبي كـ User logon name / sAMAccountName.
   - UPN بالشكل `trainingnumber@cti.org`.
   - الحساب Enabled.
5. اختبر حساباً تجريبياً عبر خدمة مرتبطة بـLDAP إذا كانت سياسة العمل تسمح بذلك.

---

## 17. قواعد تشغيل مهمة للموظفين

1. **لا تعدل السكربتات** أثناء التشغيل الاعتيادي.
2. حدّث `users.xlsx` فقط.
3. لا تغيّر اسم `users.xlsx`.
4. لا تغيّر ترتيب الأعمدة A-E.
5. اجعل D وE من نوع Text في Excel.
6. أغلق Excel قبل تشغيل السكربت.
7. شغّل PowerShell كمسؤول.
8. شغّل `0-Run-All-CTI-Student-Replacement.ps1` للعملية الاعتيادية.
9. إذا فشل VERIFY، أصلح Excel أو التعارض ولا تتجاوز الفحص.
10. لا تنقل OU الطلاب أو تعيد تسميتها بدون تحديث الحزمة رسمياً؛ السكربت مصمم للمسار الثابت المذكور في هذا الدليل.
11. احتفظ بتقارير كل تشغيل حسب سياسة القسم.
12. بعد الانتهاء، احمِ أو احذف `users.xlsx` إذا لم تعد هناك حاجة إليه، لأنه يحتوي كلمات مرور بنص صريح.

---

## 18. ملاحظات أمنية

ملف `users.xlsx` يحتوي كلمات مرور Plain Text لأغراض الإنشاء، لذلك:

- لا ترسله بالبريد أو تطبيقات المحادثة بدون آلية معتمدة.
- لا تتركه في مجلد مشترك مفتوح.
- قيد صلاحيات NTFS على مجلد العمل.
- احذفه أو انقله إلى موقع آمن بعد اكتمال المهمة حسب سياسة المؤسسة.
- لا ترفق كلمات المرور في تذاكر الدعم أو التقارير.

ملفات التقارير لا تسجل كلمة المرور نفسها.

---

## 19. ملخص سريع للموظف

إذا كانت البيئة طبيعية والملف جاهز، المطلوب فقط:

```powershell
cd C:\ADImport
powershell.exe -ExecutionPolicy Bypass -File .\0-Run-All-CTI-Student-Replacement.ps1
```

ثم:

- إذا ظهر `VERIFY = FAIL`: توقف وأصلح الخطأ.
